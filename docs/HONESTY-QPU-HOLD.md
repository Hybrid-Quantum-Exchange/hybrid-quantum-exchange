## Publication checklist

Before publishing or updating a result or status claim:

- [ ] Label the evidence accurately: `LOCAL_SIM`, classical, estimate, UI shell, or `REAL_QPU`; do not present one category as another.
- [ ] Give claims a date and link the reproducible method, source artifact, and run receipt where applicable. A proposed CI gate or documentation page is not a passing run.
- [ ] Make yield or fidelity claims only when supported by identified measured data and its protocol; otherwise say that no verified value is available. Never invent, project, or imply a measured value.
- [ ] Make speedup or quantum-advantage claims only with reproducible results and a stated classical baseline.
- [ ] Describe the DeepNet master as an external documentation link only; do not imply verified availability, integration, runtime, schema, or QPU access.
- [ ] Keep status explicitly dated and distinguish a documentation snapshot from live service or hardware status.
- [ ] Keep the QPU hold and operational boundaries intact: no QPU, secrets, settings, billing/IAM, invites, DeepNet runtime/schema, or FIRE work.
